# 真机验证

设备：8GB M1 iPad Pro 11 英寸第三代，iPadOS 27.0.1。编译环境：Apple Silicon Mac、Xcode 27.1、Release、真实 iPad Metal。记录日期：2026-10-16。

## 模型下载与生命周期

19 项真实设备检查全部通过，包含：

- 管理接口鉴权、固定 revision 目录、非法模型拒绝、当前模型删除保护。
- iPad 直接从模型源下载，取消并等待结束；取消后原 4B 仍可生成。
- 切后台暂停下载，回前台后重试。
- 完整下载 Qwen3-0.6B-4bit，335,450,584 字节权重及配置/tokenizer 文件；通过文件大小、架构和 LFS SHA-256 校验。
- 加载下载模型，API 报告实际模型，生成正文“你好！”（2 个原始输出 token），计数与库一致。
- 拒绝旧模型 ID；重启后恢复选择并从本地加载；切回 4B；删除非当前模型。

另外进行了加载失败注入：修改 0.6B 测试模型的层数配置以触发加载错误，确认自动恢复上一 4B 模型，之后恢复原始测试配置。测试模型随后按删除测试清理，预装 4B 保留。

完整下载先由下载实现完成，随后安装进度修正版本，验证缓存跨 App 更新、加载、重启、回退与删除。进度修正另外做在途字节与取消检查；不将 8B 的部分下载描述为完整下载或运行验证。

可重复运行（会下载并删除 0.6B，要求已安装且激活默认 4B）：

```sh
python3 Scripts/test-model-management.py --report .local/model-management-verification.json
```

可选传入 `--device-id` 和 `--bundle-id`，增加真实前后台与重启检查。显式添加 `--exercise-fallback` 会在待删除的 0.6B 测试模型中注入无效配置，以验证加载失败回退；这不修改默认 4B。

## 推理与持续性能

4B 此前完成约 20.17 分钟连续测试，79 次正式生成、20,224 个输出 token：解码速度中位数 17.64 token/s，前约 2 分钟汇总 24.25，末约 2 分钟 14.76。温度压力由 normal 到 serious，但不能将全部速度变化归因于温度；未严格控制室温、供电、亮度等条件，也未比较 llama.cpp。

另有独立的 10 次 API 容量短测，每种输入长度测两次，各输出 128 token：

| 输入 token | 解码中位数 token/s | 设备首 token 事件中位数 |
|---|---:|---:|
| 45 | 24.83 | 0.54 秒 |
| 429 | 24.41 | 3.34 秒 |
| 941 | 23.55 | 6.81 秒 |
| 1453 | 22.70 | 11.89 秒 |
| 1965 | 21.87 | 17.66 秒 |

这组短测内核 footprint 峰值约 3.303GB，不是最大上下文/最大输出所有组合的峰值证明。按输入从短到长执行，未控制顺序。短请求约 25 token/s 不替代 20 分钟持续结果。

本项目未宣称达到 M1 最优利用率。8B 4bit/3bit 是可下载候选，其完整运行、持续性能与质量仍需另外验证。

## 最终版本 API 回归

自主下载版本在 USB 转发和 Wi-Fi 局域网各通过 35/35 项端到端检查，覆盖鉴权、非法输入、上下文预算、SSE/普通回复、Unicode 一致性、usage、并发拒绝与断线恢复。四个模型管理写入路由另行验证无令牌请求均为 401。

修正下载进度后，真实开始官方 8B 4bit 下载，确认权重仍在传输时 progress 超过 0.0045，超过配置/tokenizer 小文件能够贡献的比例；随后取消并确认未标记安装。此项只验证在途字节进度与取消，没有完整下载或运行 8B。磁盘余量仅在 iPad 本机显示与用于空间检查，不通过管理 API 返回。

```sh
python3 Scripts/test-ipad-api.py --output .local/api-verification.json
```

完整生命周期下载最初在功能版本进行；最终进度修正版本继续验证缓存跨更新、模型加载、重启恢复、失败回退、删除和上述 API 回归。测试未将不同版本记录混为一次性能基准。

## 加载按钮与续传修复

修正了未安装时隐藏“加载”的界面：按钮始终显示，未完成下载/校验时明确灰显原因，并显示实际字节容量。新下载器将数据分块写入持久 partial 文件，取消或网络失败后保留前缀，重试校验 HTTP Content-Range；源忽略 Range 时截断后重下，避免重复拼接。旧临时权重仅按固定 revision 的 64KiB 前缀 SHA-256 匹配后恢复，完整文件仍重新校验 SHA-256。

独立真实 HTTP 测试 10/10：正常下载、取消、续传、服务器忽略 Range、错误 Content-Range、503、断流、断流后恢复、过长响应及已完整前缀。运行：

```sh
python3 Scripts/test-download-transport.py
```

修复版本的真机验证确认：旧下载中有 3.26GB 的权重前缀与固定模型指纹匹配并被恢复；后续累计约 3.83GB 的文件在 App 更新后仍保留。恢复 0.6B 缓存并完成全部文件校验后，installed=true，可激活且生成“你好！”，随后切回 4B；8B 再次开始时从保留的位置续传。这些检查不代表 8B 已完成下载或运行。校验循环按块释放临时数据，避免大模型校验累积整份文件内存。
